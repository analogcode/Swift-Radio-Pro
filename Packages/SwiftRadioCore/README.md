# SwiftRadioCore

An iOS 17+ Swift 6 library containing the radio catalog, observable stores, playback boundary, artwork loading, and outgoing Handoff. The shipped app instantiates it: `AppEnvironment` builds one set of these objects at launch and the SwiftUI scene and the UIKit CarPlay scene delegate share that instance.

Run the isolated Swift Testing suite from **this package directory**:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild test -scheme SwiftRadioCore \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro,OS=27.0' \
  -derivedDataPath ~/Library/Developer/Xcode/DerivedData/SwiftRadio-swiftui
```

The app project's generated package scheme does not include the package test action. Use the package-directory command above. This package imports UIKit and MediaPlayer; macOS `swift test` is not supported.

## Composition and ownership

Create one app-lifetime `PlayerService`, `StationsStore`, `ArtworkLoader`, `NowPlayingInfoPublisher`, and `RemoteCommandsController`. Phone and CarPlay must share them. Do not activate the audio session at launch or on scene activation: `PlayerService` activates a non-mixable `.playback` session itself when `load(url:)`, `play()` or `seek(to:)` is called, so opening the app never stops other apps' audio. Those calls stay synchronous for callers, but the engine only receives the stream, Play or seek after the activation has finished: the session applies its category when it activates. Activations run one at a time, and any later transport command supersedes a pending one, so Stop, Pause or a new selection during activation wins and the superseded request never reaches the engine (a stream stopped this way is loaded by the next `play()`). While a new station waits, the previous stream is stopped and the player reads idle and buffering. If activation fails, the player stops and reports `.failed`, never Playing; the next tap or Play command retries. The adapter sets `FRadioPlayer.configuresAudioSession = false` before first accessing `shared`; SwiftRadio alone owns category setup and activation. The category is re-applied on each activation. Pass `mixesWithOtherAudio: true` only if the app should play under other audio; a mixable session cannot own lock-screen, Control Center or CarPlay Now Playing.

Inject the engine, publisher, and commands into `PlayerService`, then inject that service and a loader into `StationsStore`. Bind commands once with `bind(player:stations:)`: without a current station every command reports `.noActionableNowPlayingItem` and does nothing, so a stray headset press cannot start the radio. The controller removes registrations on `unbind()` or destruction. Do not run the legacy audio setup and new composition simultaneously: the vendor engine and system media centers are process-wide resources.

`StationsStore.select` supplies station display fallbacks and starts loading the stream. When a reload drops the current station the store calls `PlayerService.unload()`, which stops transport, clears the engine's `radioURL`, and removes system Now Playing info (nil, not an empty-title media card). Late metadata callbacks cannot recreate that card without a selection. `play()` then does nothing until another station is selected, so a late remote Play cannot resume a removed stream. Keep the navigation shell alive after initial loading; refresh state is not navigation state.

After awaiting station artwork, compare the current station ID and call `updateArtwork(_:for:artworkURL:)` with a nil URL. For track artwork, compare both station ID and the requested metadata URL, then pass that URL. The service rejects obsolete IDs/URLs and immediately reveals cached station artwork when the track URL becomes nil. FRadioPlayer 0.4 rejects superseded lookups. The app retains its own station/track identity checks for image downloads and injected late events, and keys accepted artwork to the station that was current when it arrived. `ArtworkLoader` shares one download per URL and cancels it when the last waiting caller is cancelled. Asset resolution uses the app bundle by default; tests can inject a bundle.

All six engine events use application-owned values. The private adapter exists because FRadioPlayer's nonoptional duration, vendor metadata, and seek completion parameter cannot witness the `RadioPlaying` signatures directly. FRadioPlayer 0.4 guarantees main-actor observer delivery. The adapter retains `deliverOnMainActor` as a defensive boundary: it delivers inline on the main thread, preserving ordering, and hops for explicitly injected background events. Remote-command callbacks always return the action's real status. On the main thread the action runs inline; from any other thread the callback blocks on `DispatchQueue.main.sync` until the action has run. That cannot deadlock because nothing on the main actor waits for a MediaPlayer callback queue. Next and Previous report `.noSuchContent` when there is no other usable station. Their MediaPlayer target closure is explicitly `@Sendable`.

`RadioPlaying.seek(to:completion:)` uses FRadioPlayer 0.4's exactly-once, asynchronous main-actor completion. The engine completes even when no item or duration is available, and seeking preserves a paused or stopped transport state.

`PlayerService` still reads the current engine duration before entering the seek flow, so live streams do not seek or resume through a stale file duration. It publishes the requested position immediately and ignores intervening time events until completion. A generation token prevents an older completion from releasing a newer seek or resuming a different station; loading, pausing and stopping invalidate that token. **Resume-on-scrub is app policy:** only the still-current completion explicitly resumes playback. The `.vendor` test fake models the 0.4 contract; controlled stale completions and adversarial events verify the app's guards independently. Real-engine tests use the published dependency.

FRadioPlayer handles interruptions and route changes. It resumes after an interruption only when playback was active at its beginning, the system allows resumption, and no intervening user command superseded it. An unmatched interruption end does nothing; losing an audio route pauses. The service retains its transport-intent guard so an unexpected Playing event cannot override an explicit Pause or Stop or reach the lock screen as playing. An engine-originated pause does not itself become a user pause.

The package and app project both require the published `0.4.x` series (`.upToNextMinor(from: "0.4.0")`). Both lockfiles resolve 0.4.0 at `8fff8f5f220acb1640e6cca9b18f9ca61f45075a`. Validation uses this remote package, with LNPopupUI 4.0.1 and LNPopupController 4.5.12 in the app graph.

Playback-clock ticks update the observable `elapsed` only. The system advances lock-screen elapsed time from the published rate, so a file that is rebuffering publishes rate 0 (and 1 again once ready) while its transport intent stays playing; live streams keep rate 1 because they publish no clock. For the same reason, the Now Playing dictionary is rebuilt only on transport, readiness, metadata, artwork and duration changes, and once on the first tick after a seek completes (the engine lands near, not on, the requested second).

`CatalogListContent` maps the catalog to a size-limited list such as CarPlay's. A catalog longer than the item limit is split into pages: every page but the last holds `limit - 1` stations and a More row that opens the next one. The page count is capped by the caller (the CarPlay scene allows four list pages so Now Playing still fits the five-template depth); stations beyond that are reported in `hiddenCount`, as they are when the limit leaves no room for a More row.
